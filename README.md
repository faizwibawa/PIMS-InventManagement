# PIMS — Personal Inventory Management System

A mobile-first web app for keeping track of personal belongings: what you own, where it is, its current status, and quick "pack lists" of items to check before you head out. The UI is in Indonesian (Bahasa Indonesia). The app also adapts to a desktop sidebar layout on wider screens.

> Scaffolded with [Figma Make](https://www.figma.com/make/). The package name is `figma-make-app` and `vite.config.ts` ships Figma Make dev plugins.

## Features

- **Autentikasi** — email/password sign up and sign in via Supabase Auth, with email-confirmation handling and `full_name` captured at registration.
- **Inventaris** — add, edit, view, and delete items. Each item tracks category, quantity, status (`available` / `borrowed` / `unavailable`), who borrowed it, notes, image, icon, associated quick sets, and a location-change history.
- **Lokasi** — hierarchical locations: Tempat → Ruangan → Penyimpanan → Posisi spesifik, each flagged as stored (`Disimpan`) or carried (`Dibawa`).
- **Quick Sets** — named bundles of items (e.g. a "Kuliah" set) with optional reminders (days + time) and check results, so you can confirm everything is packed before leaving.
- **Goods Check** — run through a quick set and mark items as checked/ignored.
- **Notifikasi** — reminders and alerts for unchecked, borrowed, or unavailable items, with read / read-all.
- **Dashboard** — summary counts, today's activity (active quick set with progress), and an attention list for items needing action.

## Getting started

Prerequisites: Node 22 and pnpm (both pinned in `.mise.toml`; [mise](https://mise.jdx.dev/) will install them automatically).

```bash
pnpm install
pnpm dev        # start the Vite dev server (default port 8443)
```

> When running inside Figma Make, the dev server is already started for you and reachable through the preview panel. Running `pnpm dev` is only needed for local development.

Other scripts:

```bash
pnpm build      # production build
pnpm preview    # preview the production build
pnpm format     # format with oxfmt
```

## Configuration

Supabase connection details live in `utils/supabase/info.tsx` (`projectId` and `publicAnonKey`). This file is autogenerated by Figma Make — avoid hand-editing it. The anon key is a public, RLS-gated key by design, not a secret.

The frontend data layer (`src/lib/inventory.ts`, `src/lib/quicksets.ts`) calls the Edge Function at:

```
https://<projectId>.supabase.co/functions/v1/make-server-e8f7ac83
```

sending the signed-in user's access token as a bearer header plus the anon `apikey` header.

## Backend status

⚠️ **The Edge Function is currently a stub.** `supabase/functions/server/index.tsx` only sets up CORS, request logging, and a single health endpoint:

```
GET /make-server-e8f7ac83/health  ->  { "status": "ok" }
```

The routes the frontend expects are **not implemented yet**:

- `GET/POST/PUT/DELETE /inventory`, `/inventory/:id`
- `GET/POST /locations`
- `GET/POST/PUT/DELETE /quicksets`, `/quicksets/:id`, `POST /quicksets/:id/check`
- `GET /notifications`, `PUT /notifications/:id/read`, `PUT /notifications/read-all`

Until these are added (the imported `kv_store.tsx` is intended to back them), inventory, quick sets, and notifications will fail to load against the live backend. Auth works, since it uses Supabase Auth directly rather than the Edge Function.

## Conventions

- Components use default exports.
- Use double quotes for strings containing apostrophes (an unescaped apostrophe in a single-quoted string breaks the build).
- Styling is Tailwind v4 utility classes in JSX; global CSS and theme customization go in `src/index.css` (keep `@import` statements first).
